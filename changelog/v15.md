# v15 — Portable ship and PR guides

Ship and PR each have one runtime-neutral guide.
Claude and Codex discover ordinary entrypoint files; both read the same guide.
Repo-specific configuration and reviewer instructions remain owned by the repo.

## Catch up: preflight before any older catch-up

When crossing v15, do this preflight before applying any missing version, even if an older changelog says to copy files or edit the old paths.
The v15 migration replaces older ship/pr copy and path-edit instructions; apply unrelated historical changes normally.
Do not stamp a version or commit an update until all required changes are complete and conflicts resolved.

1. Inventory `.agents/ship.md`, `.agents/verify.md`, `.agents/ship/`, `.agents/pr/`, `.claude/skills/{ship,pr}/`, `.agents/skills/{ship,pr}/`, `.claude/agents/ship/` and any other configured agent or skill paths.
   Record symlinks, their targets, untracked files, extra files and all destination collisions without following a symlink into an unrelated directory.
   Do not modify a symlink target; do not remove an external or shared symlink without the user's approval.
2. Identify the actual installed baseline using `.agents/repo-setup-version` and repo-setup's git history; compare every existing file to the corresponding historical template, not just the latest template.
   An absent version, unavailable or ambiguous baseline, local edits, unknown files, differing copies, symlinks, or an occupied destination require inspection and a proposed per-file merge.
   Show differences and ask the user to resolve ambiguities before changing affected files; preserve originals until the merged result is accepted.
   Do not assume a file is unmodified because its name matches a template.
3. Preserve `.agents/ship.md`, `.agents/verify.md`, reviewer scope, runtime mappings, model choices, delivery and gate policy, writable paths, and every repo-specific instruction.
   Apply the other applicable historical config changes as proposals, retaining the user's choices; never infer missing runtime mappings.
   If v14 is missing, adapt its role manifest and runtime map only after resolving the existing choices with the user.
4. For each file, copy only into an absent destination or leave an identical ordinary file in place.
   For a differing destination, propose a merge and apply only the user's accepted resolution; preserve both originals until then.
   Keep unknown and customized files, including specialist references, and carry accepted customizations into the appropriate canonical guide or agent.
   Update paths in the manifest, agent prompts, their references and any repo instructions only after checking their meaning; do not perform blind replacements in customized content.
5. Copy `templates/shared/ship/` to `.agents/ship/` and `templates/shared/pr/` to `.agents/pr/`, merging accepted customizations per file.
   Move or copy each configured repo-specific agent and its references from `.claude/agents/ship/` to the corresponding `.agents/ship/agents/` path; update its internal paths and manifest references.
   Copy `templates/entrypoints/ship/SKILL.md` and `templates/entrypoints/pr/SKILL.md` to each of `.claude/skills/` and `.agents/skills/` under the matching skill directory as ordinary files.
   Preserve legacy files until their content is accounted for and the user accepts removal; never remove unrelated files or a shared symlink target.
6. Verify all configured roles resolve to existing documents, all `.agents/ship/references/` links resolve, both runtimes' ship and pr entrypoints point at the canonical guides, and no unresolved legacy references remain in active instructions.
   Confirm both runtime model maps exist for the runtimes actually used.
   If any conflict remains, stop, report it, and leave the version stamp unchanged.
   Once complete, write `15` (or the latest fully applied version) to `.agents/repo-setup-version`.

For a new repo, fill the repo-specific templates as described in `references/01-ship.md`.
The repo-specific ship config template now records prompt paths for specialist roles; adapt the filled manifest without changing responsibilities.
